# Kumiki のレビューの約束

**レビューは日本語で書いてください**

開発ルールの大本は `docs/development.md` ここはレビューで見てほしい点だけを抜き出したもの
CodeRabbit（`.coderabbit.yaml`）と Qodo（`.pr_agent.toml`）にも同じ約束を渡している

## ソース（`src/kumiki/`）

- コメントは日本語で「なぜそう書いたか」を説明するもの 何をしているかを言い換えただけのコメントは指摘する
- TODO / FIXME / XXX をコードに残さない
- 文章に句点（まる）を使わない 文の途中は半角空白で区切る 機械の検査（`tools/punctuation.py`）があるので個別の指摘は不要 逆に「句点が無いので文として不完全」という指摘もしない
- `src/kumiki/core/` は GUI に依存しない ここで PySide6 を import していたら指摘する
- モデル（Project / Timeline / Clip）の変更は必ず `Command` 経由 直接書き換えていたら指摘する
- 座標の Y は上が正 新しく位置を扱うコードで下向きになっていないか見る
- 型は mypy strict で通る `type: ignore` に理由が書かれていなければ指摘する

## 互換層（`src/kumiki/compat/`）

- 未対応のものを黙って捨てていないか `CompatibilityReport` に記録してから先へ進むのが約束
- 1 種類読めないだけで、ファイル全体を例外で止めていないか
- 形式の判定を、名前空間やアセンブリ名など版で変わるもので行っていないか（クラス名だけで振り分ける）

## テスト（`tests/`）

- テスト名とコメントに「壊れたときに何が起きるか」が書かれているか assert が通ることだけを書いたテストは指摘する
- GPU・ffmpeg・特定のフォルダなど、実行する機械の状態に依存するテストは、無いときに飛ぶようになっているか

## CI（`.github/workflows/`）

- CI は手元の `tools/verify.py` と同じものを走らせる 片方だけに検査が増えていたら指摘する
